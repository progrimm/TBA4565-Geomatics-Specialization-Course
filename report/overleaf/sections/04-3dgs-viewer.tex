\section{3DGS Viewer}\label{sec:p3}

\subsection{Purpose}

3D Gaussian splatting \citep{kerbl2023} is a fairly new method for capturing real places and objects in 3D from ordinary photos or video, and it is starting to appear in GIS and digital-twin software. I wanted to find out what a splat file contains and how it can be shown in a web browser. The project started as a CesiumJS globe with a gallery of georeferenced splats, but was rebuilt as a viewer for local files when the gallery data turned out to be unavailable to me (\cref{sec:challenges}). The user opens their own splat file, and the file is read in the browser without being uploaded anywhere.

\subsection{What a splat file contains}

A splat scene is a large number of small, semi-transparent 3D ellipsoids (Gaussians). Each one has a position, a size along three axes, a rotation, an opacity and a colour that changes with the viewing direction. A mesh describes surfaces, and a point cloud has points without size; a Gaussian has both an extent and an orientation. The Gaussians are fitted so that the scene looks like the input photos from every camera position, which is why splats can look very realistic.

The most common file format is PLY, where each splat is one record with a list of named values. The header of my own test capture lists 154\,055 splats with 62 values each. Of these, 45 describe how the colour changes with the viewing direction, as spherical-harmonic coefficients of degree 3. This explains why splat files are large, and why compressed formats such as SPZ \citep{spz} and SOG \citep{playcanvas-sog} exist.

\subsection{The viewer}

The viewer uses Spark \citep{spark}, a splat renderer built on three.js \citep{threejs}. It has four functions:
\begin{itemize}
  \item Open a file (PLY, SPZ, \code{.splat}, \code{.ksplat} or SOG) with a file dialog or by drag and drop.
  \item Show facts about the file, read from the PLY header by the app's own code: number of splats, values per splat, colour degree and extent (\cref{fig:p3-upaxis}). A PLY file without splat properties, for example a mesh, is rejected with a message.
  \item Change which axis points up, and reset the view.
  \item Measure the distance between two points.
\end{itemize}
Captures often contain stray splats far away from the scene, called floaters. If the camera were placed to show the full extent, the scene would appear small in the middle of the screen. The viewer therefore frames the central 96\,\% of the splats along each axis.

To measure, the user clicks two points. Each click sends a ray from the camera through the mouse position into the scene, and the first splat it hits is used. The distance is the straight line between the two points in the file's own coordinates.

\subsection{Splats as geodata}

Testing with real files showed what a splat file does \emph{not} contain. It has no coordinate reference system, and it does not record which way is up. My capture was upright with $-Y$ up, the usual convention for 3DGS training output, but lay on its side with $+Z$ up, the usual convention in GIS (\cref{fig:p3-upaxis}). The file also has no known scale. The distance across the lid of the jar (\cref{fig:p3-measure}) is 1.075 ``units'', and nothing in the file says what a unit is. To use a splat in GIS, it has to be georeferenced, for example with GNSS positions for the photos or with ground control points. It can then be placed on a globe as 3D Tiles with the glTF extension for Gaussian splats \citep{3dtiles,khr-gaussian-splatting}, which is what the first version of this project tried to show.

\subsection{Limitations}

Only uncompressed PLY files have been tested in the browser. The other formats depend on Spark's loaders and have not been tested here. The whole file is read into memory, and the largest file tested was 47\,MB. The app's JavaScript is 1.17\,MB (compressed) and has to be downloaded before a file can be opened. Measuring needs a mouse or touch screen.
