\section{One website}\label{sec:website}

The three apps are built and published together as one static website on GitHub Pages \citep{ghpages}. A script builds the homepage and the three apps into one folder, and a GitHub Actions workflow publishes it whenever the main branch changes. Making this work taught me a few practical things about web deployment: every app has to load its files from relative paths so that it works under its own sub-path, a backend cannot run on a static host (hence Projection Lab's static mode), and secrets such as the Cesium token must come from the build system rather than the code. Each project also has its own automatic checks (linting, unit tests and a build) that run on every change, and the apps were checked in a browser at desktop and phone width (\cref{fig:mobile}).

\section{What I gained}\label{sec:reflection}

% TODO (author): adjust this section to your own experience.
\paragraph{GIS understanding.} Each project turned a topic from the course into something I could see and test. Projection Lab made map projections concrete: I now understand \emph{why} Mercator exaggerates the far north, not just that it does. Trondheim 3D showed how much of GIS systems work is about making data from different sources agree: Norwegian and global coordinate systems, two kinds of height, a WFS service, OpenStreetMap and Cesium's streamed tiles. The 3DGS Viewer showed both how impressive Gaussian splats are and how far they still are from GIS use without georeferencing.

\paragraph{Technologies.} I now have hands-on experience with a web GIS stack from database to browser: PostGIS, Python geospatial libraries and an API on the server side, and D3, CesiumJS and three.js in the browser, with React for the interface. I also learned the tooling around them: Docker, automated tests, continuous integration and static hosting.

\paragraph{Working with an AI assistant.} The assistant made it possible to finish three working apps in the time available, but it changed what my work was. Instead of typing code, I spent my time deciding what to build, reading and understanding the code, and checking the result. Three habits made this work: writing the rules down for the assistant (for example, never report a number that has not come from running code), requiring a runnable check for every change, and looking at the screenshots myself. The tutoring phase of Projection Lab was the part where I practised writing code myself; in the later projects the learning came more from directing and reviewing.

\paragraph{Keeping it small.} Choosing small, clearly scoped projects and finishing each one properly worked better for learning than one large project would have. The change of plan in the 3DGS project was a useful reminder to check that data is actually available before building on it.

\section{Conclusion}\label{sec:conclusion}

The module gave me practical experience with three sides of GIS: the science behind map projections, the systems needed to combine real geodata in a 3D city model, and a new 3D data type on the web. All three apps are finished, documented and online at \siteurl.
